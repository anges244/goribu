# R2

R2 support is being implemented in batches. This checkout validates bucket
configuration, generates bindings, and provides `req.r2` for local development
and production builds, including signed downloads. Production bucket and secret
provisioning, domain connection, and browser upload helpers are not implemented
yet. Keep this work unreleased until those batches are complete; deployment does
not yet provision or check R2.

## Configuration

Declare buckets in `goribu.config.js`:

```js
import { defineConfig } from "goribu/server";

export default defineConfig({
  name: "my-app",
  compatibilityDate: "2026-09-01",
  r2: {
    name: "my-app-media",
    domain: "media.example.com",
    private: { name: "my-app-files" },
    jurisdiction: "eu",
  },
});
```

Goribu supports one default bucket and an optional second private bucket.

| Configuration | Generated bindings |
| --- | --- |
| `r2: { name: "my-app-files" }` | `R2` for a private default bucket |
| `r2: { name: "my-app-media", domain: "media.example.com" }` | `R2` for the bucket intended for public files |
| The example above | `R2` and `R2_PRIVATE`, both with EU jurisdiction |

Names must contain 3 to 63 lowercase letters, digits, or hyphens, and start and
end with a letter or digit. The two buckets must have different names.

`domain` is a bare hostname with at least two labels, such as `media.example.com`.
Hostnames are normalized to lowercase. Single-label names such as `localhost`,
schemes, paths, ports, IP addresses, trailing dots, and `r2.dev` hosts are rejected.
Declaring a hostname currently records the configuration only; it does not
connect a domain or make a bucket public.

`private` accepts only `name` and requires a `domain` on the default bucket.
For one private bucket, use `r2: { name: "my-app-files" }`.

Omit `jurisdiction` for the default jurisdiction, or set it to `"eu"` for both
buckets. Unknown fields are rejected. `defineConfig()` takes an immutable
snapshot, including the nested private-bucket declaration.

Goribu writes the bindings into its generated `goribu.wrangler.jsonc`. When
`r2` is configured, handwritten `r2_buckets` declarations in `wrangler.json`,
`wrangler.jsonc`, or `wrangler.toml`, including named environments, fail during
development, build, and deployment setup. Configure at most two buckets through
`r2` in `goribu.config.js`.

Development uses local buckets and needs no R2 credentials. The generated
configuration uses bucket names directly; local data persists across development
server restarts. Production builds retain the same names and jurisdiction.

For an R2 app, `goribu dev` creates `.goribu/dev-secret` on first serve and reuses
it across restarts. It supplies this generated value as `GORIBU_SECRET` to the
local Worker only. Cloudflare keeps loading root `.env`, `.env.local`, or
`.dev.vars` normally; an app-defined `GORIBU_SECRET` takes precedence. The
generated secret is absent from `goribu.wrangler.jsonc` and production output.
Removing `.goribu/dev-secret` regenerates it on the next serve and invalidates
local signed links that used it.

Automatic creation of production buckets belongs to the upcoming provisioning
batch, so a passing local build does not mean the buckets exist on Cloudflare.

## The request API

Handlers and middleware receive `req.r2`. It exposes the native Workers R2
methods: `head`, `get`, `put`, `delete`, `list`, `createMultipartUpload`, and
`resumeMultipartUpload`. Their options, streaming bodies, conditional results,
errors, and multipart objects pass through. In particular,
`resumeMultipartUpload()` returns its multipart object synchronously. See the
[Cloudflare Workers R2 API reference](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)
for those contracts.

```js
export async function GET(req, res) {
  const object = await req.r2.get("config/homepage.json");
  if (!object) return res.notFound();
  return res.json(await object.json());
}
```

`put(key, value, options?)` adds one convenience: a `File` or `Blob` with a
nonempty `type` supplies `httpMetadata.contentType` when none is specified.
An explicit content type wins, whether metadata is a plain object or `Headers`.
Goribu preserves the caller's options and headers without modifying them.

```js
await req.r2.put("exports/latest.csv", csvBlob);
await req.r2.put("exports/latest.csv", csvBlob, {
  httpMetadata: { contentType: "text/csv", cacheControl: "no-cache" },
});
```

With a second bucket configured, use `req.r2.private` for the same native methods.
It has no `url()` method. Without a domain, the default `req.r2` is itself the
private bucket; a second bucket is unnecessary.

`req.r2` always exists, but operations throw an actionable configuration error
when no bucket is declared. Async methods return rejected promises, including
for configuration and binding errors; `url()`, `resumeMultipartUpload()`, and
accessing an unconfigured `req.r2.private` throw synchronously. Each binding
resolves only on its first storage operation in a request.
Unused R2 configuration therefore does not require a binding at runtime.

## Public URLs

Store object keys in your database and derive URLs when needed:

```js
const url = req.r2.url("avatars/a b.png");
// Production: https://media.example.com/avatars/a%20b.png
// Development: /_goribu/r2/public/avatars/a%20b.png
```

`url(key)` is synchronous and needs only configuration, so it works during
prerendering without accessing storage. It requires `r2.domain` and does not
check whether the object or production domain exists. Each path segment is
percent-encoded, preserving slashes. Empty keys, invalid Unicode, and `.` or
`..` path segments are rejected; browsers would normalize the latter into a
different path.

In development, the internal public-file endpoint streams from the default
local bucket, with stored HTTP metadata, ETag revalidation, and HEAD support.
It uses `Cache-Control: no-cache` so edits are revalidated. It cannot serve the
private bucket or a default bucket without `r2.domain`. This helper is removed
from production builds, where `/_goribu/r2/public/*` returns 404; production
public files must be served by the configured custom domain.

Files served on the app's own origin—both this dev endpoint and Worker-served
signed downloads—always receive `Content-Security-Policy: sandbox` and
`X-Content-Type-Options: nosniff`. These fixed headers prevent uploaded HTML or
SVG documents from running scripts with the app's origin privileges. They apply
to partial, conditional, and error responses too, and override app-wide header
defaults. Stored content types are preserved; these endpoints do not support
serving active application pages. Public custom-domain and S3 responses are
served separately and do not pass through this header policy.

## Signed downloads

Both `req.r2.signedUrl(key, options?)` and `req.r2.private.signedUrl(key, options?)`
return a promise for a time-limited GET URL. Check the current user's authorization
in your handler **before** creating the link: anyone holding the URL can use it
until it expires, without passing through route middleware again.

```js
// After checking that the current user may read this invoice:
const downloadUrl = await req.r2.private.signedUrl(invoice.fileKey, {
  expiresIn: 600,
  download: "invoice.pdf",
});
return res.json({ downloadUrl });
```

`expiresIn` defaults to 900 seconds and accepts integers from 1 to 604800.
`download` requests an attachment filename; it must contain 1 to 255 characters
without slashes or control characters. Unicode names use an encoded filename
alongside an ASCII fallback. Keys must be valid Unicode, at most 1024 UTF-8 bytes,
and have no `.` or `..` segments.

In production, supplying both `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY` in
the Worker environment selects an S3 SigV4 URL. `goribu deploy` supplies
the internal `GORIBU_R2_ACCOUNT_ID` Worker variable from the authenticated account
it selected for deployment. The shell's `CLOUDFLARE_ACCOUNT_ID` remains an input
for account selection. Standalone builds require no account credentials.
EU buckets use the account's
`.eu.r2.cloudflarestorage.com` endpoint. A partial credential pair fails with a
repair instruction. Credentials are used only inside the Worker, never sent to
the browser as raw values. The resulting signed URL is itself a credential.

Without those keys, and always in development, the URL targets
`/_goribu/r2/file?t=…` on the request's origin. It requires `GORIBU_SECRET` in
the Worker environment. This endpoint verifies the token's purpose, signature,
expiry, and bucket before accessing storage. It streams GET responses, supports
HEAD and single byte ranges, and answers ETag revalidation with 304. Failed
`If-Match`/`If-Unmodified-Since` preconditions return 412; unsatisfiable ranges
return 416. Responses use `Cache-Control: private, max-age=0`.
Worker-served files use `Content-Security-Policy: sandbox` and
`X-Content-Type-Options: nosniff`, so uploaded HTML or SVG cannot run scripts as
the app.

The prerender harness rejects `signedUrl()` calls: an expiring URL must not be
frozen into static HTML. Automatic candidates fall back to Worker rendering.
For an explicitly prerendered route, remove `prerender = true` or set
`prerender = false`. Rotating `GORIBU_SECRET` invalidates existing Worker-served
links; S3 links use the separate R2 credentials.

Automatic production provisioning is coming.
