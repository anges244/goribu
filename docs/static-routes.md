# Static routes

Some routes never need the Worker to answer them. If a page's first response is
the same for everyone and can be produced ahead of time, Goribu renders it once
at build and serves it from Static Assets — Cloudflare's CDN — so the Worker is
not invoked for successful document loads or client navigation to that page.

This is not a separate "prerender feature" you turn on. Static output is simply
what the build does when a route's first response needs no Worker.

## Two independent things

Two questions are easy to run together, and Goribu keeps them apart:

- **Where does the response come from?** A static asset, or the Worker.
- **Does the browser run JavaScript for it?** Every route hydrates (from Block
  5); that is a separate axis.

A "static" route is only a statement about the first question. A page with no
server work and a `useState` counter is served statically *and* hydrates in the
browser — both are true at once. Static never means "no JavaScript." (A
route-level opt-out of hydration is a possible future feature, not part of this
version.) See [decisions.md](./decisions.md).

## What makes a route static

By default, a route is served statically when both hold:

1. **The route needs no request-time handlers.** The route has a page and no explicit HTTP handlers, has not set `prerender = false`, and has no selected middleware. A page exporting POST, PUT, PATCH, DELETE, HEAD, or OPTIONS stays on the Worker so Static Assets cannot shadow its handlers.
2. **Its URL is fully known at build time.** A route with a dynamic segment
   (`posts/[id]`) has no single URL to build, so it cannot be static.

You can be explicit with a `prerender` export:

```jsx
export const prerender = false; // always serve this route from the Worker
export const prerender = true;  // require this route to be built statically
```

`prerender = true` is a promise: if the route cannot be built statically, the build fails rather than quietly serving it from the Worker. It can explicitly opt a GET handler into build-time rendering. Combining it with any non-GET handler is a build error: remove the export or move those handlers to a separate action route.

A page containing `<Form>` can still be static when its handlers live at another URL. For example, a static `/subscribe` page can submit `<Form method="post" action="/subscriptions">` to a separate `/subscriptions` route exporting `POST`. Colocating the handler and page also works; that URL is then served by the Worker.

## How it works

`goribu build` produces the Worker and client bundles, then runs the **built
Worker itself** in the Workers runtime and asks it for each static route. The
HTML it returns — exactly what the Worker would serve at request time — is
written into the client asset directory. Cloudflare then serves that file
directly, without invoking the Worker. The build also saves the HTML's exact
props and metadata as a navigation payload and records the successful route in
a build-identified index. Client navigation and prefetch fetch these assets
instead of running the Worker. Failed prerender candidates are never advertised
as static.

Because the static file is produced by the real Worker, a static route and a
dynamic one render through the same code and the same document shell; there is no
second rendering path to drift.

## One snapshot for both navigation paths

A static page uses the same build-time props and metadata for document loads and
client navigation, including pages with an explicitly prerendered GET handler.
Query strings can change the browser URL and client UI, but do not rerun static
GET handlers or server metadata functions. Set `prerender = false` for output
that must depend on the current request.

Clicking a Link to the exact current static URL scrolls to the top without
fetching, rerendering, or resetting component state. Other static navigation
still loads saved data, page JavaScript, and CSS as needed. The static guarantee
is no request-time Worker execution, not zero network traffic.

Development continues to use the Worker; production snapshots are generated by
`goribu build`. Publish the whole completed build together. Missing or invalid
snapshots and incompatible deployments trigger a safe document load. Ordinary
anchors and navigation before hydration continue to use document requests.

## Downgrades are loud

When a prerender candidate can't be made static, the build says so by name and
falls back to serving it from the Worker:

```
[Goribu] Route "src/routes/posts/[id].jsx" (/posts/:id) is a prerender candidate
but was not statically output: it has a dynamic segment (:id) whose URL is not
known at build time. It will render on the Worker at request time.
```

A route is downgraded when it has a dynamic segment, selected middleware, or the
Worker cannot render it at build time. A non-HTML response or one that sets a
cookie also cannot become a public static snapshot, and neither can a page whose
`Suspense` boundary throws: the HTML would contain only the fallback. A route that *forced* `prerender = true`
fails the build instead of downgrading — it asked for a guarantee it could not
keep.

## Assets and routes cannot collide

Static Assets take precedence over the Worker, so a file you publish under
`public/` that sits at a route's URL would shadow that route. The build refuses
it: if a published HTML file resolves to a URL a route owns, the build fails and
names the file and the route. Rename or remove one.

## Verifying it

The payoff of a static route is that it costs no Worker invocation, and that is
measured, not assumed. After a deploy, hitting a static route does not increment
the Worker's invocation count, while a dynamic route does. Verify client-side
links and prefetch as well as direct document requests. That check against
real invocation counts is what closes this capability — the build output alone is
not taken as proof.
